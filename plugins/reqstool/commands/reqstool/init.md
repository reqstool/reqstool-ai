Initialize reqstool-ai configuration for this project by creating `.reqstool-ai.yaml`.

## Steps

1. **Check for existing config**

   If `.reqstool-ai.yaml` already exists in the project root, read it and ask the user
   if they want to update it or start fresh.

2. **Scan the project for reqstool files**

   Look for existing reqstool YAML files to auto-detect the project structure:
   - Search for `requirements.yml` and `software_verification_cases.yml` files
   - Look for existing URN references in those files
   - Identify system-level vs subproject directories by checking for `filters` keys

3. **Gather config values**

   Use **AskUserQuestion** to collect or confirm each value. Pre-fill with detected values
   where possible:

   - **URN**: The project URN (check existing reqstool YAML files for `urn:` fields)
   - **Revision**: Version string for new requirements/SVCs (default: `"0.1.0"`)
   - **System path**: Path to the system-level reqstool directory containing the SSOT
     requirements and SVCs (look for the directory with non-filter `requirements.yml`)
   - **Modules**: For each subproject module:
     - **Name**: Module identifier (used in commands like `/reqstool:add-req <name>`)
     - **Path**: Path to the module's reqstool directory
     - **req_prefix**: Requirement ID prefix (e.g., `CORE_`, `CLI_`)
     - **svc_prefix**: SVC ID prefix (e.g., `SVC_CORE_`, `SVC_CLI_`)

   Ask if they want to add more modules after each one. Stop when they say no.

4. **Write the config file**

   Write `.reqstool-ai.yaml` to the project root with the collected values.
   Include helpful comments explaining each field.

   Format:
   ```yaml
   # reqstool-ai configuration
   # Generated by /reqstool:init

   urn: <urn>
   revision: "<revision>"

   system:
     path: <system-path>

   modules:
     <name>:
       path: <module-path>
       req_prefix: <prefix>
       svc_prefix: <svc-prefix>
   ```

5. **Verify**

   If `reqstool` CLI is installed, run `reqstool status local -p <system.path>` to verify
   the config points to valid reqstool files.

6. **Report**

   Show the user the created config and remind them:
   - Add `.reqstool-ai.yaml` to version control
   - Run `/reqstool:status` to check requirements traceability

## Guardrails

- Never overwrite an existing `.reqstool-ai.yaml` without asking first
- Use detected values as defaults but always confirm with the user
- If no reqstool files are found, still create the config with placeholder values and tell the user to fill them in
